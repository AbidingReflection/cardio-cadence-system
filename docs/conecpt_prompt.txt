Current workflow:

Over several months I worked up to doing longer and longer elliptical workouts at the Cedar city aquatic center gym.  I have a Polar OH1+ arm heart rate monitor that I use to measure my HR readings continuously during my sessions.  I am resistant to being locked into any protietary data ecosystem so I use my Google Pixel Pro 7 running gadgetbrige to collect the data into an easily query-able SQLite db.  During a session I use a multiscreen display of Pulsar (To show instantaneous HR during a session and a PWA of Strudel with code to play different sounds for each left and right footfall in order for me to achieve a target cadence RPM.



Strudel Code:

let spm = 40         // strokes per minute

let cps = spm / 60

setcps(cps)

seq("bd hh").s().gain(0.8)

End Strudel Code

This defines the duration, resistance levels and target RPM for each segment of a workout.  Following a workout I export the gadetbridge data on my phone then send it to my debian laptop or debian PC  via KDE connect to access in order to run my python HR data analysis pipeline.  This is a config driven pipeline that generated HR zone graphs based on the thresholds set in the config.  An example graph output is attached.  I then have a separate script that can create a calendar view of workouts in a given range for easy viewing and habit consistency analysis.



I'm very pleased with the overall results of the HR pipeline but there are some issues.  Right now I have a series of Google Sheets that generate my cadence schedules based on parameters for a Warm-up, Primary phase and cooldown.  This can linearly increase RPM and resistance based on the input parameters but I'd like the ability to generate more dynamic schedules based on more complex phases.  Also, since the current system relies on my manually updating the spm in strudel RPM changes need to be minimized.  I'd like to be able to set parameters for a phase that can gradually increase or decrease RPM automatically.  Also, currently I have to take a screenshot of my pulsar display at the end of the workout to capture the end time of the workout and manually enter that time when I run the HR graph analyzer in order for it to correctly query the SQLite db.  Ideally I could have the cadence controller program generate the cadence ques and capture the start and end of the workout then produce a file that would contain all the data needed to query the HR db.
