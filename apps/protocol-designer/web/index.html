I'd like to re-think the phase/block layout approach. Blocks will have: Block Label (Label) Cadence Ramp Type Label (Cadence Ramp Type) Cadence Variable Start Label (RPM Start, SPM Start) depending on activity Cadence Variable End Label (RPM End, SPM End) depending on activity Non-Cadence Ramp Type Label (Cadence Ramp Type) Non-Cadence Variable Start Label (Resistance Start, Incline Start) depending on activity Non-Cadence Variable End Label (Resistance End, Incline End) depending on activity Each phase and block will also have a collapsed and expanded state. Phases: - Collapsed - Display duration total (Duration: 18:00) - Display block count (4 Blocks) - Expanded - Add Phase Block header above all phase blocks - Label - Cadence Ramp Type - RPM Start, SPM Start (Dynamic based on activity) - RPM End, SPM End (Dynamic based on activity) - Show blocks - Start collapsed Blocks: - Collapsed - Display attributes corresponding to phase block header - Should be aligned to header layout - Expanded - Remove attribute values - Populate Combo box for Cadence Ramp Type & Non-Cadence Ramp Type - Horizontal divider between Cadence & Non-Cadence sections - For both sections Populate Ramp Type specific variable fields - Steady - Start [Variable] - Smooth - Start [Variable] - End [Variable] - Stepped - Start [Variable] - End [Variable] - Step Interval - Populate an Apply & Cancel Buttons in the bottom right - Triggers block level model update - Validates and triggers error message if validation is not passed - Upon success model is updated and block is collapsed - Upon error, message displayed and block is not collapsed, new values remain - Upon cancel, model is not updated and block is collapsed.
